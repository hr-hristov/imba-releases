Document check

Find where a set of documents contradicts itself before it goes out.

Several agents and people write one offer at once, each on their own part. The proposal promises 12 months of warranty while the specification demands 24, and nobody reads both pages side by side. /rd reads every document, compares every statement twice, fixes only mechanical slips, and asks about everything else with one recommended answer.

On a phone, each key on this page is a tap.

01Start

Start a check with /rd.

Type /rd in a spawn that works in the documents' folder. After against, name the reference document, the one every other must agree with, such as a tender's technical specification; after source, the sheet the figures come from. With no reference document named, the run only plans: it reads and compares everything and changes nothing. Before any reviewer starts, the agent says how many reviewers and rounds the run takes, on which model, and what share of this login's five-hour usage allowance it costs, then waits. Yes starts it. In each round, readers list every statement, hunters compare the statements on one subject, and checkers test them against the references, the sources and the laws cited. Another round runs only after a round that wrote a fix, up to the round limit, three unless Settings say otherwise. When a cited law turns out longer than counted, the agent asks again before going on.

02The card

Read the ending first.

The run ends on a Document check card, and its first line is the ending in its colour: Clean in green, 3 questions left in amber, Not passed in red. Beside it, 3 fixed alone counts the slips fixed without asking. A square stands for each round, on the right on a laptop and under the ending on a phone: grey for a round that found or wrote something, green for one that found nothing new, red for one that failed, and empty for a round still running or never run. imba prints every figure on the card from its own record of the run, and the agent writes none of it.

03A question

Each question comes with an answer.

Each question stands in its own box: the statements that cannot both be true, each with its document, section and point, and last the document that decides it, its words lit. On a laptop they stand side by side; on a phone one under another, with “or” between the two that clash and “and” before the one that decides. Under them, the warning sign says what the answer sets off: the price offer prices warranty support for 12 months, and the offer becomes the contract. Recommended gives the one answer that weighs it: 24 months, and support repriced for 24.

04Figures

Figures are checked in their source.

Readers installed: the proposal says 5,005 in point 2.4 and 4,981 in Annex 2. Neither page can settle the other, so the check reads the installations sheet named as the source, which says 5,002, and recommends 5,002 in both places. The words at the top right of each box say how sure it is: proven when a reference, a source or a redone sum shows it, sure when two hunters found it and the spawn's agent confirmed both sides cannot be true, likely when one hunter found it. A likely find, such as the delivery time below it, is always a question and never fixed.

05Answer

Answer, and it is written everywhere.

The agent asks the questions one at a time, in the card's order, each with its recommended answer. Say yes to take it, write the value you want instead, or ask to keep the documents as they are. imba writes your answer as a tracked change and carries it to every other place that still says the same old words: 24 months went into point 3.1 of the proposal and row 7 of the price offer. A reference document or a source is never written. A later answer on the same subject replaces the earlier one. After the last answer, another round reads everything again and a new card follows. Here Annex 2 still says 4,981, so one question is left, and the band Your answers, carried to every place lists each answer with its places. An answer given after the round limit is written but not read again, and the agent says so.

06Fixes

What it fixes on its own.

Only mechanical slips are fixed without asking: a point reference left behind by renumbering, a defined term written small, and a Latin letter inside a Cyrillic word. They stand under Fixed alone, as tracked changes by Dana Whitfield, the author set on Settings, so Word shows each one for review and its Reject undoes one. Before the first change, imba also copies each file to a folder on the server outside the checked folder. Every figure, date, sum, warranty, scope or duty is a question instead. An Excel formula is never changed, a PDF never edited, and a reference or source never written. imba reads a file again before it writes, and writes nothing if the file changed since. Before any reviewer starts, imba runs its own checks at no cost: blanks left unfilled such as XX or ___, template notes, a year that differs from the document's own, and every table sum and Excel formula worked out again. Explained says why a difference is no fault, and Client comments without a reply lists each Word comment nobody answered.

07Not checked

What it could not read.

The card's foot counts what was done: 4 documents read whole, 214 statements compared twice, 2 law citations checked, 16 sums redone. The last line always says what was not checked, here pages 2 and 3 of the delivery protocol, scanned with no text layer. The check reads Word files whole, with headers, footers, footnotes, text boxes and comments, Excel and CSV with their formulas, PDF, PowerPoint, OpenDocument, markdown and text. It cannot read old .doc, .xls and .ppt files, or scanned pages; an old file saved in the new format is read next time. A law whose text cannot be fetched is named as unverified. One run reads up to 300 documents of up to 64 MB each. A Clean card carries the last line too, and reads Not checked: nothing only when nothing was left out.

08Endings

Not passed, and Clean.

A run ends Not passed when a step fails imba's checks three times, when a fix comes back after another writer undid it, or when the round limit is reached while the run is still writing fixes. Its last line names the step that failed, here the check step of round 1, and the agent offers to run the check again. A run ends Clean when a round reads every document again and finds nothing new, with no question left: here round 2, once the 21 devices taken down became 12. A Clean card still names what was not checked, here an old .xls file.

09Plan only

With no reference, nothing changes.

A run with no reference document named, or started as /rd plan, changes nothing. Its card says No reference documents named, nothing changed, its questions stand as on any card, and Would fix alone lists the slips a real run would fix, each struck through beside its fix. The agent then asks whether to name a reference document. Name one after against, or on Settings, and run /rd again.

10Message

Tell the owner in one press.

Message on the card, or x on a laptop, asks the agent for a short note to the documents' owner from the newest check. The agent shows who it goes to and the exact words, and sends it by Slack only after your yes. Nothing is sent from the card itself.

x The note

11Settings

Set what every run starts from.

Settings › Spawns › Document check holds what every run starts from. Reviewer picks Claude or Codex, its model and its effort, and Account the login the reviewers run on. Readers, Hunters and Checkers set how many of each a round deals out, from 1 to 6, with at least 2 hunters. Round limit runs from 1 to 20, 3 to start with. Mechanical fixes off makes every find a question. Author of changes signs every tracked change, and starts as the server's git user name. Card language is English or Bulgarian. Reference documents lists the names every run checks against: Add puts one in, and the cross takes one out on its second press. Law sources and Look for follow. A number or name saves on Enter or when you leave its field; a switch or choice saves on the press.

12In Bulgarian

The card in Bulgarian.

With Card language set to Bulgarian, the card reads in Bulgarian: Проверка на документи, 1 въпрос остава, Препоръка, Непроверено, and НЕ е минало for a run that fails. The agent asks its questions in the card's language too. A blank left unfilled in a document, such as в срок до XX дни, is asked under the subject незапълнено място on a card in either language.

Every law a document cites is fetched from the law sources and checked, and /rd also takes code and a repository to check what the documents promise against the code, or batch to check each generated document against its row in a sheet.

Every word and button

Each press, and its key.

The chapters above use a few of them. Here is all of the Document check: the words typed after /rd, the card's button and the Settings page. Keys need a keyboard; on a phone or tablet the buttons are taps.

Typed after /rd

Words after /rd change that one run, in any order.

  • against and a fileNames a reference document the others must agree with.
  • source and a fileNames a source of figures, such as a database export or a signed protocol.
  • code and a repositoryAlso checks what the documents promise against that repository's code.
  • batch, a folder, from and a fileChecks each generated document in the folder against its row in the sheet.
  • key and a columnNames the sheet's column that matches a generated document to its row.
  • rounds and a numberSets this run's round limit, from 1 to 20.
  • planReads and compares everything, and changes nothing.
  • claude or codexRuns this run's reviewers on that agent instead of the one Settings name.

On the card

  • MessagexAsks the agent for a note to the documents' owner, which it sends only after your yes.

On Settings › Spawns › Document check

A number or name saves on Enter or when you leave its field; a switch or choice saves on the press.

  • ReviewerClaude or Codex, its model and its effort.
  • AccountThe login the reviewers run on: Best seat, Host, or one by name.
  • Readers, Hunters, CheckersHow many of each a round deals out, from 1 to 6, with at least 2 hunters: readers list the statements, hunters compare them, checkers test them against the references, sources and laws.
  • Round limitThe most rounds a run takes, from 1 to 20, 3 to start with.
  • Mechanical fixesWhether slips are fixed alone, or every find is asked.
  • Author of changesThe name every tracked change is signed with, at first the server's git user name.
  • Card languageEnglish or Bulgarian; a Bulgarian card that fails reads НЕ е минало.
  • Reference documentsThe names every run checks against, in order, up to 20. Add puts one in; the cross takes one out on its second press.
  • Law sourcesWhere a cited law's current text is fetched from: lex.bg and eur-lex.europa.eu to start with. Add and the cross work as above.
  • Look forFigures, Dates, Duties, Scope, Names, Logic, Units, References, Language and Laws, each switched on or off.
